# 同步點子苗圃心智圖

點子苗圃是使用者用來思考點子的網頁，裡面的心智圖有一個「實作」分支。
你的任務是維護 repository 根目錄的 `IDEA_MAP.md`，讓使用者匯入後，「實作」分支能反映目前真實的實作狀態。

## 步驟

1. 讀取現有的 `IDEA_MAP.md`。
   - 不存在時，讀取 `CLAUDE_TASK.md` 中「【實作】」底下的內容作為起點，以及「行動步驟」清單。
   - 兩者都沒有，就從空白開始。
2. 回顧這次工作實際做了什麼：看這次對話、`git diff`、`git log` 最近的提交。只寫真的發生過、看得到證據的事。
3. 把新內容**合併**進既有的「【實作】」，而不是只寫這次的內容：
   - 保留仍然成立的項目。
   - 狀態有變的項目要移動，例如從「進行中」移到「已完成」，或把已解決的「問題與風險」改寫成結論後移到對應的組。
   - 刪掉已經不成立的項目，例如被推翻的技術選型。
   - 合併意思重複的項目。
4. 依照下方的格式，完整覆寫 `IDEA_MAP.md`。
5. 最後用一兩句話告訴使用者這次更新了哪些重點，並提醒他到點子苗圃按「匯入 Claude Code 整理」。

## 分組

「【實作】」底下只使用下列組名。沒有內容的組不要列出，順序照下面排：

- 架構
- 模組與功能
- 技術選型
- 資料與介面
- 已完成
- 進行中
- 待決定
- 問題與風險

## 寫法規則

- 每個項目 30 字以內，用繁體中文，寫結論，不寫過程。
- 每組最多 8 項。超過時，把最舊、最瑣碎的「已完成」項目合併成一句概括。
- 使用者還沒拍板的事放「待決定」，不要自行假設答案寫進其他組。
- 可以提到檔案或模組名稱，但不要貼程式碼。
- 「完成的行動步驟」必須**逐字沿用** `CLAUDE_TASK.md` 行動步驟清單裡的原文，點子苗圃靠原文比對打勾。沒有對應的原文就不要列。
- 「建議的下一步」最多 5 項，動詞開頭，每項 30 字以內。

## 格式

嚴格依照下面的格式。「【實作】」那一行不可縮排，組名縮排 2 個空格，項目縮排 4 個空格，全部用「- 」開頭。

```markdown
# 點子苗圃同步：<點子標題>
更新時間：YYYY-MM-DD HH:mm

【實作】
  - 架構
    - 項目
  - 已完成
    - 項目
  - 待決定
    - 項目

## 完成的行動步驟
- 行動步驟原文

## 建議的下一步
- 下一步
```

點子標題沿用 `CLAUDE_TASK.md` 第一行「實作說明：」後面的文字；找不到就用 repository 名稱。
