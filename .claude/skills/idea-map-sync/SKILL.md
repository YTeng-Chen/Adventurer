# 同步點子苗圃心智圖

點子苗圃是使用者用來思考點子的網頁（Artifact：https://claude.ai/artifact/Kv9VzDupa6YXYVdPn7SDmi）。
這個專案對應裡面的點子「冒險者遊戲」，它的心智圖有一個「實作」分支，內容來自點子筆記（`note` 欄位）裡「【實作】」底下的文字。
你的任務是在合併進 main 之後，直接改寫那段文字，讓「實作」分支反映 main 上真實的實作狀態。

## 什麼時候做

- 使用者說「合併進 main」，合併完成之後。
- 使用者明確要求整理或同步心智圖時。
- 其他時候不要改心智圖，也不要在 repository 裡產生 `IDEA_MAP.md`。

## 步驟

1. 用 `ArtifactData` 讀出點子：`action: "list"`、`collection: "data/users/me"`，找 `title` 為「冒險者遊戲」的文件，記下它的 `version`。
2. 取出 `note` 裡「【實作】」那一段（從「【實作】」那一行到下一個不縮排的段落標題，或到結尾）。筆記的其他段落（例如「【對話整理】」）一字不改。
3. 回顧上次同步以後 main 上實際做了什麼：看這次對話、`git log`、`git diff`。只寫真的發生過、看得到證據的事。
4. 把新內容**合併**進既有的「【實作】」，而不是只寫這次的內容：
   - 保留仍然成立的項目。
   - 狀態有變的項目要移動，例如從「進行中」移到「已完成」，或把已解決的「問題與風險」改寫成結論後移到對應的組。
   - 刪掉已經不成立的項目，例如被推翻的技術選型。
   - 合併意思重複的項目。
5. 用 `ArtifactData` 的 `update` 寫回 `note`（整段筆記，只替換「【實作】」那一段），同時把 `updatedAt` 設為現在的毫秒時間戳；`if_version` 帶第 1 步讀到的版本。版本衝突就重新讀取再合併，不要覆蓋別人的修改。
6. 用一兩句話告訴使用者這次心智圖更新了哪些重點。使用者不需要再按任何匯入按鈕。

## 分組

「【實作】」底下只使用下列組名。沒有內容的組不要列出，順序照下面排：

- 架構
- 模組與功能
- 技術選型
- 資料與介面
- 已完成
- 進行中
- 待決定
- 問題與風險
- 建議的下一步

## 寫法規則

- 每個項目 30 字以內，用繁體中文，寫結論，不寫過程。
- 每組最多 8 項。超過時，把最舊、最瑣碎的「已完成」項目合併成一句概括。
- 使用者還沒拍板的事放「待決定」，不要自行假設答案寫進其他組。
- 可以提到檔案或模組名稱，但不要貼程式碼。
- 「建議的下一步」最多 5 項，動詞開頭。

## 格式

「【實作】」那一行不可縮排，組名縮排 2 個空格，項目縮排 4 個空格，全部用「- 」開頭：

```
【實作】
  - 架構
    - 項目
  - 已完成
    - 項目
  - 建議的下一步
    - 下一步
```
